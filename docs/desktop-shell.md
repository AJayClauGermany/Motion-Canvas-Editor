# Desktop shell

The desktop app is the web editor's Vite build (`dist/`) inside an Electrobun 2
window. Nothing in the shell depends on the editor's contents, and the web build
is not changed for the desktop: the same `dist/` runs in a browser.

## Layout

| Path | Role |
|---|---|
| `electrobun.config.ts` | App identity, main-process entrypoint, `copy: {dist: 'views/editor'}`, release artifacts in `artifacts/desktop/` |
| `shell/main.ts` | Main process (Bun). Opens one 1440x900 window on `views://editor/index.html`, sets the application menu |
| `shell/page-scripts.ts` | JS strings run inside the webview: the error reporter (preload) and the capability probe |
| `shell/prebuild.ts` | `preBuild` hook: fails the build if `dist/index.html` is missing |
| `shell/tsconfig.json` | Type-checks the shell against the SDK in `.hutch/devkit` |
| `.hutch/`, `build/` | Generated by Hutch (gitignored) |

There is no `hutch.config.ts`. The `electrobun` npm package pins Electrobun 2.0.7
and its paired Hutch, and Bun stays the package manager.

## Commands

```bash
bun run shell:dev        # vite build, then electrobun dev (dev build + launch)
bun run shell:run        # relaunch the existing dev build without rebuilding
bun run shell:build      # vite build, then electrobun build --env=stable
bun run shell:typecheck  # electrobun prepare, then tsc -p shell/tsconfig.json
```

`shell:build` writes the app to `build/stable-<os>-<arch>/` and the installer,
update bundle and update metadata to `artifacts/desktop/`. Hutch does not
cross-compile; build each platform on that platform.

Environment variables read by the main process:

| Variable | Effect |
|---|---|
| `MCE_SHELL_URL` | Start page instead of `views://editor/index.html`, e.g. `views://editor/harness.html`, or `http://127.0.0.1:5273/` to use a running `bun run dev` server with HMR |
| `MCE_SHELL_PROBE=1` | After `dom-ready`, log one `[shell] probe {...}` line with the webview's capabilities (`new Function`, `eval`, 2D canvas, `localStorage`, `MediaRecorder` types, secure context) |
| `MCE_SHELL_PROBE=<file.js>` | Run that file in the page instead. It can report with `__electrobunSendToHost({type: 'shell:probe', ...})` |

## Seeing page errors

- The preload in `shell/page-scripts.ts` sends uncaught errors, unhandled
  rejections and failed script/style/image loads to the main process, which
  prints them as `[shell] page error {...}`.
- Dev builds also forward the page's `console.*` calls to the terminal as
  `[webview:1] [console.error] ...` (an Electrobun feature, dev channel only).
- View > Toggle Developer Tools opens the web inspector (macOS and Windows; see
  limitations for Linux).

Stable builds are quiet: in the sandbox the stable run printed no main-process
or webview output to the terminal.

## Web platform notes

- The shell sets no Content-Security-Policy and Electrobun adds none, so
  `new Function` and `eval` work. `views://` is a secure context
  (`crypto.subtle` and `navigator.clipboard` exist).
- Asset URLs stay relative (`base: './'` in `vite.config.ts`), so
  `views://editor/index.html` resolves `./assets/...` inside the bundle.
- WebKit's storage (which holds `localStorage`) is per channel, on Linux under
  `~/.local/share/dev.motioncanvaseditor.app/<channel>/WebKit/`.

## Verified in the cloud sandbox (2026-11-21)

Linux x64, WebKitGTK 2.52.6 (`libwebkit2gtk-4.1`), Xvfb, Electrobun 2.0.7.

- `bun run shell:dev` builds and opens the window. The editor UI renders
  (code pane, preview, timeline, "Ready") with no page errors reported.
  Screenshot: `artifacts/shell/index.png`.
- `MCE_SHELL_URL=views://editor/harness.html` with a probe that calls
  `window.harness.run()` on `examples/square-to-circle/scene.civet`: compiles
  and renders (`ok: true`, no diagnostics, 91 frames, 1920x1080 canvas).
  Screenshot: `artifacts/shell/harness.png`.
- Capability probe on `views://editor/index.html`: `new Function`, `eval`,
  2D canvas, `localStorage`, `canvas.captureStream`, secure context all true.
- Error reporter self-test: an uncaught error, a rejected promise and a missing
  `<script src>` each produced a `[shell] page error` line.
- `MCE_SHELL_URL=http://127.0.0.1:5273/` loads the Vite dev server and connects
  its HMR socket.
- `bun run shell:build` produces `linux-x64-MotionCanvasEditor-Setup.tar.gz` and
  the update bundle in `artifacts/desktop/`. The stable bundle starts and renders
  the page (`electrobun run --env=stable`; `artifacts/shell/index-stable.png`,
  taken while the editor UI was still a placeholder).

Sandbox commands (the sandbox tooling is not needed on a normal machine):

```bash
bunx electrobun --version            # once, BEFORE sourcing hutch-env.sh (see below)
source tools/sandbox/hutch-env.sh
bun run build && bunx electrobun build --env=dev
xvfb-run -a -s "-screen 0 1440x900x24" bash -c '
  MCE_SHELL_PROBE=1 bunx electrobun run --env=dev & pid=$!
  sleep 12; import -window root artifacts/shell/index.png; kill $pid'
```

The first `electrobun` call downloads the paired Hutch with Node's `https`
module, which rejects the `http://127.0.0.1` relay URL that `hutch-env.sh` sets
(`Protocol "http:" not supported`). Run it once without the relay; it is cached in
`~/.hutch/npm/electrobun/` afterwards.

## Known limitations

- **No application menu on Linux.** Electrobun 2.0.7 implements application
  menus on macOS and Windows only, so File/Edit/View (including Reload and
  Toggle Developer Tools) do not exist on Linux. The menu is untested: the
  sandbox is Linux.
- **macOS and Windows are untested.** Only the Linux build was built and run.
- **`MediaRecorder` in the sandbox supports no container.** The constructor
  exists, but `isTypeSupported` is false for `video/webm` and `video/mp4`.
  WebKitGTK records through GStreamer; the sandbox has only the base and good
  plugin sets. Probably a missing-plugin issue rather than a shell issue, but
  not confirmed. Check with `MCE_SHELL_PROBE=1` on a real desktop before
  relying on WebM export under WebKitGTK.
- **Native `<select>` elements render with a light GTK look** (white background
  in the dark UI) under WebKitGTK; see `artifacts/shell/index.png`.
- **`electrobun run --env=stable` installs the app.** The stable bundle is a
  self-extracting installer: running it copies the app to
  `~/.local/share/dev.motioncanvaseditor.app/stable/` and adds a desktop entry.
- **No icon, code signing, auto-update URL or file associations** are configured.
- **`MCE_SHELL_PROBE` and `MCE_SHELL_URL` are honoured in stable builds too.**
  The page has no privileged RPC, but remove or gate them before distributing
  if that is unwanted.
- If the page shows `File not found: editor/index.html`, the bundle was built
  from an empty `dist/`. A failed `vite build` empties `dist/`; the `preBuild`
  hook now stops the shell build in that case.
